# PCTS Video Tool 设计

依据本次对话重新设计和实现；旧方案目录与 Ingredients 均不作为模板、训练数据、验收样本或运行依赖。

当前交付包括独立Windows x64单文件EXE、源码与Windows一键构建包。最终使用者不要求WSL、WSLg或Python。开发使用WSL；本次成品在Wine 11中使用Windows Python 3.13.9与Windows锁定依赖构建，并在真实Windows完成冻结包及窗口后端自检。打包不替代触摸识别准确率验收。

## 已确认需求

- 一段视频预期包含10轮。每轮自动提取 press、两次灯光由亮变暗的 blink 1 / blink 2、文字首次变绿的 green，以及随后出现的 MD / TX。
- 自动结果可以直接接受；触摸不清、读数冲突、事件缺失时提供候选与人工修正。
- 按原片展示顺序从0编号，保留每帧时间戳。统一支持帧差/FPS与时间戳差两种计算方式；切换重算，不重新识别。
- 10轮全部进入统计，不自行排除第一轮。不生成未经用户规定的合格/不合格判断。
- 独立本地Windows桌面程序，优先CPU推理；无需生成式大模型、账号或运行期网络。

## 实现选择

0.3.1修复分析完成后没有结果反馈：分析结束单独处理，显示轮次与待确认数、选择首条待复核结果；0轮明确弹出原因。用户随后逐轮复核、确认并导出，无需再启动分析。

此次运行日志暴露了检测帧率误用：原片`base_rate=90000`，而相邻PTS间隔中位数对应240 fps。标志采样和事件持续帧数改用PTS估算帧率，用户设置的计时FPS保持独立。

同次原片还存在灯光高亮饱和与彩色背景。灯光改用区域平均亮度，只在亮灯状态跟随基线，保留一帧暗脉冲；文字从本次视频的清晰PRESS HERE帧提取二值字形，在扩展区域及有限缩放下比较黑/绿字形匹配分数，减少背景色与轻微位移干扰。过渡间隔较大或匹配偏弱的green保持待复核。诊断保留字形、匹配分数与位置。没有引入外部示例模板、训练或新的模型依赖。

0.3版增加整段测试范围：自动识别PRESS HERE出现与消失，连续缺失确认后回溯结束边界；部分文字或短暂遮挡不立即结束。先确定范围，再提取有效区间的事件信号；结束后的画面不参与轮次、OCR读数或测量判断。保留原片帧索引，可通过“有效片段”手工确认起止。日志同时保存标志检查与边界依据，任务格式3兼容读取格式1、2。

0.2版将ROI统一为四角的8个归一化坐标，旧矩形仅在读入入口转换。UI允许四点点击和角点拖动；OCR使用透视校正后的区域，灯光与原始颜色统计使用原始像素的多边形掩码，帧索引和时间轴保持原片含义。0.3.1的字形跟踪另在透视校正后的区域进行。

轮次需要稳定黑字准备、对应灯光、变绿响应及黑字复位。短暂掉绿不会直接结束一次响应，确认后回溯到首次绿色帧。只有孤立灯光或没有灯光对应的颜色变化时保留异常候选，不自动制造结果行；缺失轮次仍可人工补充。不按预期10轮强行截断。

每次分析自动建立本地诊断目录，记录输入任务、逐帧信号、检测参数、候选及配对、结果和异常。用户通过“导出诊断包”主动导出当前运行记录；不自动收集或上传原视频。

采用 PySide6 + PyAV + OpenCV，RapidOCR读取数字，MediaPipe定位指尖。首次框选灯光、文字、数字、触摸观察区域；机位设置可保存。框选是实现选择，后续可用自动定位替代。

与全自动寻找画面对象相比，先框选区域减少定位误差；与自行训练模型相比，现成模型可立即评测。这一版不训练模型。

触摸位置模型不等于接触检测器。首版从指尖运动变化估计候选帧，缺少可验证接触证据的候选必须保留待确认状态；不以未校准评分伪装已达到自动确认准确率。其他事件分别检测，保留缺失/多余轮次供修正，不用10轮强行截断。

数据只存一套：视频信息和逐帧时间、ROI、轮次、字段来源与确认状态。保存为JSON，导出自建Excel和关键帧证据，不读取任何历史工作簿。Excel记录帧号及时间、输入读数、所选口径下的每轮结果与统计。未完整确认可导出明确标记的草稿。

任务采用后台扫描，分析期间暂停编辑。先完成一次分析再复核，避免引入并发编辑和复杂修订框架。模块按视频、检测、识别、计算/数据、导出和界面职责划分，不做可插拔接口体系。

时间戳模式表示媒体时间轴；变速视频不能据此直接声称测得真实物理耗时。界面明确说明这一点。

## 0.3.2反馈与后续精度方案

用户确认0.3.1的20次灭灯正确；新运行记录为`20261118-140431-056760`，选区与上一次复现不同。用户逐帧校对第6轮green=2058、第10轮green=3468，当前结果2062、3475分别晚4帧、7帧。这两个人工值仅作为本次验证依据，不写入算法规则。

本次直接实现两项明确修改：分析启动时切换到查看模式并隐藏选区叠加，保留复选框和重新框选自动显示；MD/TX解析允许完整TX标签与前一个数字直接相邻，仍拒绝数字中的非法字符，不推测遗漏的小数点。

以下是待实验验证的精度方案，并非0.3.2已实现：

- green：现有黑/绿字形分别全区域取最大分数，可能落在不同位置。建议每轮黑字阶段锁定PRESS HERE的位置与笔画，允许局部跟踪，在同一批笔画像素上看黑色减少、绿色增加。多个字或分区共同变化后，用后续帧确认并回溯首帧；低置信边界保留复核。避免只降低整体绿色阈值，否则会加重背景误报。优先使用已有OpenCV能力，不训练新模型。
- MD/TX：当前读数ROI同时包含下方PRESS HERE，整体最小OCR分数会受无关文字影响。先定位完整数字行、留边距、校正倾斜，再尝试RapidOCR已支持的单行直接识别；识别评分只对应目标数字行。在同轮读数稳定阶段增加不同原帧，多种预处理同一帧不能计为多帧一致。原图与颜色分离可互相核对，小数点/负号缺失或冲突不得靠数值范围猜测。注意RapidOCR的`use_det`调用参数会保持状态，标志OCR必须显式恢复检测。
- press：目前仅从指尖减速提候选。建议固定机位、固定触摸落点和接近方向，使侧面镜头能看清指腹与屏幕之间的间隙，再结合间隙闭合、局部轮廓形变和停留判断。二维辅助线可作为接触位置参考，悬空手指也能投影越线，不能单凭越线认定接触。手部关键点用于定位；模型深度不是到屏幕的距离。
- 如允许更改器具，可考虑接触传感器驱动独立LED，需校准动作阈值与首次物理接触的延迟。应用收到触摸后显示标记测到的是处理后的响应，不能替代原有press定义。如果彩色背景属于用例负载，不应为识别而删除它；仅在允许调整测试界面时考虑给数字行留固定高对比底色、增大字体。

参考现有能力：[OpenCV模板匹配](https://docs.opencv.org/4.x/d4/dc6/tutorial_py_template_matching.html)、[RapidOCR参数](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/parameters/)、[MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker?tab=Python)。

## 0.3.3进度与格式约束邻帧补读

本次用户明确要求底部可视化进度，以及根据固定`MD:XXX TX:XXX`格式在识别失败帧前后补读。数字允许整数或一位小数，沿用负号支持；不把XXX解释为固定三位，不猜测遗漏的小数点。

采用现有OCR与邻帧搜索，不更换模型：初始读取本轮三个时点；标签/冒号缺失、数字超过一位小数、置信度不足、独立帧不足或读数冲突时，在原帧附近按±1、±2、±4、±8、±16帧检查。实际原片证明邻近画面会重复受相同背景干扰，因此随后增加本轮其他时点的覆盖，总计最多追加48帧；覆盖间隔依据视频帧率与本轮长度确定。只访问本轮green到黑字复位前的区间，不借用下一轮读数。

至少三个不同原帧得到一致的高置信完整数值才可自动接受；任何有效数值冲突保留复核，在详情列出候选及支持帧数。候选排序不代表真值，重复漏点也可能获得较多票。已有MD/TX行时只使用该行的评分，无关PRESS HERE误读不影响数值行评分。所有尝试及时记入`ocr-checks.jsonl`，取消时也可诊断。

底部进度条按阶段及已处理帧/轮次推进，不用计时器伪造进度：模型准备、起止检测、事件扫描、触摸与初始读数、邻帧补读。成功保存结果后达到100%，失败或取消显示相应状态；尚无总数的读取阶段显示活动指示。百分比反映处理进度，不承诺剩余秒数。

验证重点：非法数字不能被截断为合法前缀；整数和负值保留；无空格完整标签可解析；前后邻帧不越过轮次边界、不重复计票；冲突不被多数票静默自动确认；取消不会显示成功100%。本次实际运行日志所指原片仅用于故障复现，不进入固定测试或发布包。

## 固定机位下的press可行性检查（2026-11-18）

用户确认已固定机位、落点、接近方向，并希望联合间隙闭合、指腹形变和运动停止定位press。根据最新运行输入`20261118-154138-716286`检查`VID_20261118_152405_HSR_240.mp4`，原分辨率1280×720，触摸ROI外接范围约为x664～736、y207～270。用户暂时没有人工校对的press首帧。

可观察事实：原片能显示指腹接近与停顿，但触点位于屏幕正面内部，指腹覆盖显示内容；当前局部画面未显示可独立追踪的屏幕表面截线或清楚的成对指腹镜像。第一轮约498～507帧的图像位置趋稳只是运动现象，不作为接触首帧真值。不能把文字边缘、屏幕外边框或二值分割中消失的边缘当作间隙为零。

现有实现只对MediaPipe的8号指尖关键点取最大减速；全图缩到宽640后用于关键点推理。计划中的接触证据应从原分辨率局部图像提取，关键点只用于粗定位，不把其深度解释成到屏幕的距离。

推荐的分工与最小输入：

- 固定机位每次设置一次接触参考：复用触摸ROI，选一帧或短片段中已经明确贴住屏幕的姿态并标落点；这不要求该帧恰好是首次接触帧，但参考本身须确认确已接触。接近方向优先从轨迹估计。
- 对当前机位，先用原图局部轮廓及轨迹识别接近、短暂保持、回撤，接触参考约束候选位置。候选继续保留复核；这一方案不能凭二维重叠证明物理接触。
- 若实际落点处能同时看清指腹边缘与屏幕表面截线，再将间隙闭合作为主要证据；指腹变平、接触范围扩大和停止只作后续确认。形变可能晚于首次接触，轻触也未必有明显形变，因此不强制三项同时满足，更不采用简单的二取一/三取二投票。
- 分开记录最后明确悬空帧、最早接触候选帧和后续确认帧。最终回溯到最早有接触证据的原帧；模糊或遮挡则保留不确定区间，不返回形变最大或停止最久的帧。允许读取少量后帧用于确认，不按blink1减固定延迟生成press。
- 先用现有OpenCV轮廓/局部跟踪能力做验证，不新增重型模型或自行训练。后续有少量人工对照后，才能评估有符号帧误差、悬停误报和自动接受范围。

上述记录属于实现前的可行性检查，当时未修改0.3.3的press算法。随后用户要求实现，具体变更见下方0.4.0说明。检查用裁片保存在临时目录，不作为项目模板、训练数据或测试夹具。

## 0.4.0校准触摸候选实现

用户已要求实现上述方案。采用现有OpenCV在原图触摸ROI提取指腹轮廓，不新增模型。新增一次性校准：当前已明确接触的参考帧、接触位置的参考线两端、指腹内部取样点；三点同时确定局部肤色与参考线的手指侧。UI提供放大的触摸区域点选，校准保存到任务；修改触摸ROI会清除旧校准。

新增`touch.py`负责原图局部颜色分离、连续轮廓选择、前缘到校准位置的像素距离、前缘宽度/面积与轨迹记录。距离是图像内相对校准位置的量，不伪称物理毫米或已证明的空气间隙。没有前景时记录不可观察，不用0代替。校准模式直接使用固定ROI，不要求MediaPipe成功；未校准仍使用现有关键点候选。

判定以接近校准位置为必要条件，再观察短暂保持/局部展宽；读取少量后帧用于确认，回溯首个到位候选，不将停止最久、形变最大或blink1减固定帧数作为press。悬停未到参考位置、孤立噪点与中途不可观察有明确诊断。所有新press结果保持review，待真实人工对照后再评估自动接受。

独立审查后补充两条时序约束：按连续到位段寻找后续确认并回溯段首，即使确认发生在blink1之后也不丢失更早候选；每轮触摸搜索起点取此前全部绿色响应的结束位置，包括未配成轮次的孤立响应，避免借用前一次动作。

任务格式4兼容读取格式1～3；诊断增加校准参数、参考局部图、逐帧触摸信号与候选依据。测试覆盖到位首帧回溯、悬停、缺失边缘、方向、取消、校准保存/清除及没有手部模型的校准流程。实际原片只验证流程与可见信号，开发试验参考不作为用户确认的接触真值。

## 0.4.1三帧复核与分析用时

用户要求单击结果单元格后，视频区从左到右显示上一帧、当前帧、下一帧，可只看对应ROI，并在进度条附近显示本次分析用时。

事件字段映射：press→触摸区，blink1/2→灯光区，green→文字区，MD/TX→读数来源帧及数字区。默认裁切选区，提供全帧对照开关和返回单幅全画面入口。文字/数字/灯光沿用四角拉正；触摸区显示原图外接裁切，保留手指形状。每格标记原片帧号，中间帧就是当前浏览帧；逐帧导航同步三幅画面，浏览本身不修改测量结果。缺少候选或首尾邻帧不存在时显示明确空位，不重复边界帧冒充邻帧。重新框选切回全画面。

计时使用单调时钟，开始自动分析时重置，界面定时刷新；Worker返回结果/错误前报告最终用时，避免把用户停留在结果弹窗的时间计入。取消、失败和成功都停止并保留用时，导入/导出不重置分析计时；诊断status.json增加elapsed_seconds。

初始规则：至少24个稳定笔画像素，横向三区至少两区各有8个像素支持；总体及支持分区亮绿覆盖至少50%，笔画相对邻域绿色色差至少10。保留原确认时长及短缺口容忍，后续确认后回溯首个有证据帧；只允许提前，不把原候选向后挪，不直接取区间左端。若回溯候选破坏灭灯/green顺序，保留旧候选并提示复核。稳定笔画不足或无连续证据时也保留原候选。

所有细化结果继续review。逐帧笔画/暗色比例、分区支持、色差、参考姿态及最终选择记录到green-refinement.jsonl，detection.json保留粗检与细化来源。这是固定机位下的小范围细化，不声称已解决任意遮挡、位移或首像素过渡的不确定性。

## 0.5.0自动指腹取样与按轮运动候选

用户要求沿已讨论方案优化press，尽量减少画线。默认自动模式：在每轮搜索窗口内稀疏读取手部关键点，以手掌关键点附近的颜色作为身份线索，沿连通区域寻找触摸ROI中的指腹，并在指腹内部重新取样；采样帧仅用于找指腹，不作为接触时刻。自动取样失败时可切到手动指腹样本，只点一个清楚的指腹内部点，不要求该帧已经接触；旧参考线模式保留。

实片检查发现模型的8号食指尖偏离真正伸出的手指，不能要求该关键点落在ROI内，也不能把左右手分类分数当作检测置信度。新增motion.py实现按轮轨迹模式：从本轮清楚的指腹样本向前/后跟踪原分辨率局部区域，用颜色、区域重合与局部光流保持目标连续；不在丢失段补造位置。由本轮运动估计接近方向，将轮廓前缘投影到该方向，分析接近到保持/回撤的转折。取消所有轮次必须落入同一参考位置[-3,1.5]像素的硬条件；也不直接返回最深位置或最晚停止帧。用后帧检验转折并给出候选及复核区间，缺少真实接触证据时继续review。

UI提供自动/单点取样/旧参考线三种方式，默认自动；点选时立即显示颜色分离预览，分析后每轮可查看目标与自动方向。方向与颜色取样分开，单点不再决定方向正负。旧任务的校准信息保留供选择，不要求重新画线才能运行新版。任务格式5向后读取1～4。

验证要分别报告候选覆盖与真实帧误差；目前缺少人工press真值，不以更多候选宣称准确率提高。真实录像仅作当前流程验证，不进入训练、固定模板或发布包。仅复用已安装OpenCV/MediaPipe，不增加大型模型。


自动方向优先使用经往返误差筛选的局部光流主轴，轮廓中心轨迹作为备选；前缘转折通过连续分段直线拟合，至少两帧接近与三帧后续保持。小观察区不强制固定前窗长度，也不要求blink1之前有八帧可见；候选仍必须不晚于blink1。每轮仅缓存该窗口的原图局部裁片，用后释放，不保存全片图像序列。

对小观察区另检查前缘被四边形边界截断与可靠纹理仍持续前移；这两种情况不能因为可见轮廓位置不变而判定停止。截断导致缺失时提示扩大观察区。

## 0.6.1复核浏览性能

用户报告快速切格和前后帧操作卡顿，要求保留功能。实际旧版同一录像的88次交互测得：切格中位178.4ms，逐帧158.5ms，再次访问157.7ms；共289次read_frame/打开文件，重复定位和解码占主要耗时。

严格递增时间戳只用于定位原展示帧；缺失/重复/非单调PTS及无法对齐时沿用原read_frame索引回退，不用FPS推算帧号。分析、导出和触摸取样继续使用原有读取方法；暂不引入异步渲染、合并用户按键或改变表格信号。先验证同步优化的实测收益，确保三帧、显示方式记忆、缺失press定位、手工赋值等行为不变。

另外在相同原片比较SLICE与AUTO：SLICE切格较慢，最终保持AUTO。此次不改表格信号顺序，不用异步任务覆盖旧请求，也不改变每次前后帧的步数。
