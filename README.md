# PCTS Video Tool 0.5.2

独立开发的本地桌面工具，用视频提取10轮触屏耗时测试数据：`press / blink 1 / blink 2 / green / MD / TX`，复核后导出Excel和原帧证据。

这个项目不读取任何旧方案或演示目录，不需要历史Excel模板；可以直接搬走本目录使用。

## 当前实现与限制

- 按展示顺序解码原片，帧号从0开始；检测帧间隔和长间隔；支持中文路径。
- 灯光、变绿文字、MD/TX、触摸区域支持四点斜框与矩形框；四点可拖动微调。OCR和文字跟踪透视拉正，灯光使用原片多边形内的平均亮度。旧任务中的矩形区域自动转换。
- 自动检测两次灭灯和首次变绿；自动OCR读取数字，保留小数、负号与来源帧。多余/缺失事件保留复核。
- press默认自动寻找每轮指腹，以连续轮廓、局部光流和运动转折生成候选，无需人工画线。自动取样不理想时可单点指定指腹，方向仍自动估计；旧参考线模式可选。**所有press候选仍需确认，运动停止、轮廓展宽不能单独证明首次物理接触。**
- 手动逐帧修正、数字修改、缺失轮次补充、误检轮次删除、JSON保存与恢复。
- 帧数/FPS与视频时间戳两种计时方式可切换，重新计算无需再次识别。默认FPS为240，可修改。
- 自建Excel包含原始字段、事件时间、每轮耗时、全部轮次统计、复核状态；输出JSON和关键帧原图。
- 不使用生成式大模型；模型在安装时准备，运行期间不联网下载。
- 绿色响应持续期间的短暂遮挡/闪烁不会直接拆成新轮次；稳定黑字复位后才允许新响应。未配对灯光和变绿候选保存在检测说明与诊断记录中，不再直接两两凑成额外轮次。
- 每次分析自动保存输入任务、逐帧信号、候选事件、配对结果、运行状态与错误堆栈；可一键导出诊断包。
- 默认以PRESS HERE出现至消失限定整段测试，范围之外不检测轮次。黑字与绿字都属于标志可见，不把颜色变化当作测试结束；边界识别不确定时可手工设置原片帧范围。
- 文字变色比较当前视频的字形匹配分数，减少彩色背景干扰；字形参考从本次视频提取，不需要外部模板或训练。颜色过渡不清时保留待确认状态。
- 对已经确认的绿色响应，进一步对齐此前的黑字笔画，检查亮绿覆盖、多个文字分区与邻域色差；后帧确认后回溯首帧。只在证据支持时提前候选，不直接取复核区间左端，结果仍需复核。
- 分析完成会显示轮次和待确认数，并选中第一条待复核结果；没有轮次时弹出检测原因。
- 开始分析后自动隐藏选区框线、名称与角点；“显示选区”可随时恢复，重新选择框选区域也会自动显示，已保存坐标不变。
- MD/TX解析兼容`MD:103.2TX:0.6`这种没有空格的完整标签；仍不猜测或补造OCR遗漏的小数点。
- MD/TX严格要求完整标签、冒号及整数或一位小数，支持负值。初始三帧不够确定时，自动向前后邻帧补读，必要时覆盖本轮其他时点，每轮最多追加48帧；不跨轮读取。三个不同原帧高置信一致才自动接受，冲突显示候选并保留复核。
- 底部显示进度条和当前处理阶段。正常完成达到100%，失败或取消显示对应状态；没有总量的读取阶段显示活动指示。
- 单击press、blink 1/2、green、MD/TX单元格，左侧按上一帧/当前帧/下一帧显示对应选区；可切换三张全画面或返回单幅全画面。
- 进度条旁显示本次分析用时，开始分析清零，成功、失败、取消均停止并保留；运行诊断记录用时秒数。

0.3.1已复现用户此次报告的0轮问题：按该次运行日志中的原片与选区得到10轮候选，部分彩色背景下的变绿边界及MD/TX仍需复核。该次故障复现不等于准确率验收；触摸候选也没有逐帧接触真值。独立合成测试验证程序行为，不代替真实录像验收。

## Windows 成品使用

本次发布文件名为 `PCTSVideoTool-0.5.2.exe`；开发目录中的通用名 `PCTSVideoTool.exe` 也同步更新为这一版本。

0.5.2增加缺失单元格的悬停说明，默认开启；表格下方“缺失项提示：开／关”可切换。press使用触摸查找提示，其他缺失项使用人工填写提示；有值的单元格不显示这类提示。已有任务直接打开即可使用，保留0.5.1的显示模式记忆和缺失press查找起点。

直接运行 **`dist/PCTSVideoTool.exe`**，或解压 **`dist/PCTSVideoTool-windows-x64.zip`** 后运行其中的EXE。这是Windows x64单文件程序，包含Python运行时、视频解码依赖、OCR和手部模型；使用者不需要安装WSL、Wine、Python或模型，也不需要大模型账号。

单文件启动时会解压内置依赖，请等待窗口出现。成品已在实际Windows上通过OCR、手部模型、视频解码、Qt离屏与Windows窗口后端自检。真实录像识别精度和触摸自动确认的限制仍按上文说明，不因打包成功而视为已完成算法验收。

本次成品使用WSL中的Wine 11、官方Windows Python 3.13.9和公开Windows依赖构建；没有修改Windows加密软件或安全策略。构建环境仅用于开发，不是使用者的运行要求。

## Windows 一键构建

构建电脑先安装 **Python 3.13 x64，包含Python Launcher（py命令）**。使用公司允许的构建/发布环境；首次构建需要联网安装公开依赖。解压源码到Windows本地目录后，双击根目录的 **`build-windows.cmd`**。

构建入口会依次创建项目内 `.build-venv`、安装 `requirements-windows.lock` 中锁定的依赖、校验本地手部模型、执行测试、构建EXE、对冻结包自检。只有自检通过才生成 `dist/PCTSVideoTool-windows-x64.zip`。

构建日志：`build/build.log`。冻结包检查结果：`dist/windows-self-test.json`。如果出现加密脚本或空字节错误，应在公司允许的构建环境处理，脚本不会修改系统安全策略。

成功后直接运行 `dist/PCTSVideoTool.exe`，或者解压ZIP运行其中的 `PCTSVideoTool.exe`。构建还保留目录模式产物用于调试，但最终分发以通过自检的单文件EXE为主。开发者也可在依赖准备完成后双击 `start-windows.cmd` 运行源码界面；这个入口仅用于开发。

## 操作流程

1. 导入原始MOV/MP4等视频，等待原片索引完成，查看帧率检查信息。
2. 选择一张能看清拍摄布局的画面。先选择要框选的区域，默认“四点框选（侧拍）”，按左上→右上→右下→左下点击四角；可以拖动角点微调，右键撤销上一点，Esc取消。也可切换“矩形拖选”。灯光框贴近发光位置，**变绿文字区域应覆盖完整的PRESS HERE**，与MD/TX区域分开；触摸区包含指腹接近、落点及短暂保持，避免只框最后停住的位置；无需把整只手框入。
3. 默认“指腹设置：自动”，直接分析即可，无需画线或找已接触帧。自动选错指腹或无法取样时，再选择“单点取样”，在清楚的指腹内部点一下。
4. 点击“开始自动分析”，选区框线自动隐藏。先识别PRESS HERE起止，再分析有效区间内的灯光、变绿和读数。结束后的画面不参与轮次或统计。处理期间不能同时编辑任务；可取消。完成后直接查看表格结果，无需再次点击开始；若为0轮，查看弹窗和“检测说明”。需要查看选区时勾选“显示选区”。
5. 工具自动选中第一条待复核结果，也可在下方表格选择其他轮次。单击事件或MD/TX单元格，查看前一帧、当前帧、后一帧；右侧“查看”按钮也进入对照。左右按钮同步移动三幅画面，“设为当前帧”将中间帧填入指定字段。
6. 查看读数来源画面，必要时修改MD/TX。点击“应用修改并确认本轮”。未确认修改也会保存在任务中，但保持待确认状态。
7. 遗漏事件可以手工补轮次。删除的误检轮次需要确认；工具不自动截取最好看的10轮。
8. 选择计时方式。所有轮次统一重算，MD/TX保持原读数。
9. 保存任务或导出Excel和证据。存在缺失/待确认项或轮数不为10时，导出明确标为草稿。

快捷键：左右键逐帧、Shift+左右键跨10帧；在文字/数字输入框中不会触发帧导航。修改ROI会清空当前检测结果，界面会先提示；修改触摸ROI同时清除旧校准。任务保存格式为5，支持读取格式1～4；旧矩形区域自动转换，原片帧号不改变。

## 三帧复核与分析用时

鼠标停在显示“—”的单元格上会自动显示说明，无需先点击。press提示点击后从本轮blink1前20帧开始人工查找；其他缺失项提示进入对应复核画面并人工填写，没有可用参考帧时需使用下方导航。端到端耗时需补齐press和green后自动计算。表格下方“缺失项提示：开／关”控制这些提示，默认开启；关闭会收起当前提示，重新开启立即恢复。开关不修改测量值、当前帧或显示模式。

例如第5轮green为1702，单击该单元格后，视频区从左到右显示1701、1702、1703帧的文字选区，中间帧用边框强调。press使用触摸区原图裁切，blink 1/2使用灯光区，MD与TX都使用该轮的读数来源帧及数字区。文字/数字/灯光斜框会拉正，触摸区域保留原图形状。

取消“仅看选区”可看三张全画面，“返回全画面”回到单幅浏览；选择框选区域或进入指腹设置也会回到全画面。浏览不会自动修改结果，需点击对应的“设为当前帧”并确认。没有候选时显示空位，不能把无效浏览位置写入其他字段；视频起点/末尾缺少的邻帧也显示空位，不重复边界帧。

底部“分析用时”显示时:分:秒，从点击“开始自动分析”后的处理阶段计时，结束/失败/取消后保留。新的分析会清零，导入、导出及人工复核不会累加到该计时。诊断`status.json`的`elapsed_seconds`保存成功、失败或取消的本次分析用时。

## 指腹自动识别与单点取样

默认不画参考线。工具在每轮动作窗口内寻找手部，用手掌颜色与连通区域找到触摸区内的指腹，再从清楚的一帧向前、向后连续追踪。手部关键点只用于找目标；不会直接把某个指尖关键点或模型深度当作接触时刻。指腹失踪后停止该段追踪，证据不足则留空。

方向根据本轮轮廓轨迹和指腹纹理运动估计，不要求十轮都落入同一个参考位置。对原图前缘寻找“接近转为短暂保持”的变化，局部展宽作为辅助；可用blink1后的少量帧确认更早的转折，候选不晚于blink1。候选及复核范围表示运动证据，不是物理接触的置信区间。

分析后选择一轮，点击右侧“查看本轮触摸依据”：绿色覆盖表示选中的指腹，橙色箭头表示估计的接近方向。图中标明取样参考帧，**参考帧不是press帧**；点击表格press单元格才查看候选的前/中/后三帧。如果绿色覆盖的是背景，或箭头与实际接近方向明显不同，应修正取样或观察区后重新分析。

自动取样不理想时，点击顶部“指腹设置”，切换“单点取样”。选择一帧指腹清晰可见的画面，点击指腹内部，避开轮廓边缘、反光和背景；不要求已经接触。绿色覆盖即时预览，左键可换点，右键撤销。保存后重新分析；这一个点用于外观取样，接近方向仍由各轮轨迹决定。若皮肤与背景难以分开，界面会提示换点或调整选区。

“参考线”保留旧版方式供对照：选择明确已接触的一帧，依次点接触参考线两端和指腹内部。两端沿实际落点处的接触表面，线穿过落点；不能使用远处的屏幕外边框。该模式仍使用固定参考位置范围；默认自动模式不使用这条线。

设置随任务保存，仅适用于该视频；更改设置后未人工确认的press失效，需要重新分析。清除取样恢复自动方式；更改触摸ROI也恢复自动并清除取样。旧任务保留原校准信息，可在设置中主动选择参考线方式。所有候选继续待复核，无真实逐帧标注时不报告准确率。

## green首帧回溯

旧版复核区间表示“最后可信黑字之后，到首次绿色字形匹配达标”的可疑片段，区间左端不一定就是首绿。背景颜色或手指遮挡可能压低整体字形分数，使末端候选偏晚。

新版在响应已经确认后，对此前三帧稳定的黑字笔画进行小范围位置对齐，检查它们是否真正变成亮绿，并比较邻近背景；要求多个文字分区和后续帧支持，再回溯首个有证据帧。暗字被染绿、整个背景变绿或无法可靠对齐时，不强行提前；与灭灯时序冲突也保留原候选并提示复核。

细化在灯光、press和读数取样完成后进行，记录原粗候选与新候选。所有细化结果仍为待复核；可点击green单元格查看前/中/后三帧确认过渡。

## 有效测试片段

默认自动查找PRESS HERE：初步按约每秒4次检查文字，边界附近继续读取原片帧以细化起止。连续4次未识别到标志才确认消失；只有部分PRESS/HERE可见时继续保留片段，短暂遮挡不会立即结束。有效止帧为消失帧的前一帧，帧号始终对应原片。

如果文件结束时标志仍可见，使用原片末帧作为可用终点。若没有找到标志，或者末尾缺失持续时间不足以确认，工具会提示复核，不会静默把整段视频当作已确认测试。

点击顶部“有效片段”可改为手工指定起止帧，两端均包含。范围变化会提示重新分析；区间外的帧和时间戳异常不参与测量判断。侧拍严重、长时间遮挡或文字框不完整仍可能影响自动边界，应查看“检测说明”并修正范围。

## 自动日志与诊断包

Windows日志默认位于 `%LOCALAPPDATA%\PCTSVideoTool\diagnostics`，无需先手动保存任务。每次分析创建独立子目录，取消或失败也保留已有记录。

- `application.log`：启动版本、后台任务错误等运行信息，按大小轮换。
- `input.session.json` / `result.session.json`：视频元数据、选区坐标、计时方式与分析前后结果。
- `signals.csv`：有效区间内每帧的原片索引、时间戳、灯光平均亮度、黑/绿字形匹配分数、位置与缩放，以及原始绿色/黑色比例。
- `text-template.png` / `text-tracking.json`：本次视频提取的二值字形参考、参考帧、选区、搜索区域与缩放范围。
- `detection.json`：检测阈值、全部灭灯/变绿候选、最终配对及未配对事件。
- `green-refinement.jsonl`：黑字参考帧、稳定笔画、逐帧位置对齐、亮绿/暗色比例、分区支持、邻域色差和最终选择；`detection.json`同时保留粗检及细化来源。
- `marker.json` / `marker-checks.jsonl`：PRESS HERE识别文字、评分、帧号、起止结果和判断依据；逐次检查记录在取消或出错时也保留。
- `ocr-checks.jsonl`：每次MD/TX初读与补读的轮次、原帧号、时间戳、OCR原文、分数、格式是否合法及解析数值；逐次写入，取消也保留。
- `touch-calibration.json` / `touch-reference.png` / `touch-reference-mask.png`：当前任务的触摸校准参数、参考局部图及颜色分离轮廓。仅参考线模式生成。
- `touch-signals.csv` / `touch-detection.json`：原帧号、前缘位置/宽度、面积、连续性、光流与候选/确认帧；自动模式不输出伪造的物理间隙，参考线模式记录相对参考位置的像素距离。
- `touch-targets.jsonl` / `touch-preview-XX.png`：每轮自动/单点取样尝试与选择、指腹分离区域和估计方向；包含局部画面，随诊断包导出。
- `run.log` / `status.json` / `error.txt`：阶段进度、完成/失败/取消状态、异常堆栈。

识别异常时点击顶部“导出诊断包”，程序把当前任务的上述记录整理成ZIP，并加入当前人工修正后的任务快照。诊断包包含触摸参考及各轮指腹局部预览图，不包含完整原始视频、不自动上传。“检测说明”可以直接查看候选数量与异常帧号。0.1版未记录的逐帧诊断数据无法追溯补回，需要用新版重新分析一次。

## MD/TX补读与复核

每轮先读取三个时点。缺标签/冒号、多于一位小数、字符评分不足或数值冲突时，先检查前后1、2、4、8、16帧；仍不确定则检查本轮其他时点，合计最多追加48帧。只在本轮green至黑字复位前读取，已尝试帧不会重复计票。

完整格式不等于数值一定正确，例如`MD:753 TX:6`也符合整数格式。工具不会凭经验补成`75.3 / 0.6`；出现多种完整读数时，保留待复核状态并在详情列出候选及支持帧数。表格中的候选不能当作已确认数值，需要对照来源画面确认。

## 两种计时口径

按帧数：`(end_frame - start_frame) * 1000 / fps`。

按时间戳：`(end_time - start_time) * 1000`，使用原片各帧的展示时间（秒）。缺失时间戳不使用FPS偷偷补造。展示时间未必是真实采集时间，变速素材需要核对。

检测过程的采样间隔与持续帧数使用正向相邻时间戳间隔的中位数估算帧率，避免部分视频的`base_rate=90000`误导检测。这个内部检测帧率不会改变用户选择的计时方式或计算FPS。

每轮计算：端到端=`green-press`，HU input=`blink1-press`，HU output=`green-blink2`，MD total=`MD+TX`，HU total=`端到端-MD total`。帧事件差按所选口径换算为毫秒；不提前舍入。没有用户确认的合格阈值，因此本版本只报告测量值，不生成PASS/FAIL。

Excel统计包含所有有数值的轮次，不自动排除第一轮，另外列出计数。存在未确认输入时，统计只是草稿预览。建议在工具内修改并重新导出；直接改Excel输入不会更新本工具保存的数据或原帧证据。

## 本地开发与验证

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python scripts/prepare_models.py
.venv/bin/python -m pcts_video_tool
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
.venv/bin/ruff check src tests scripts
```

也可在WSL运行 `bash scripts/setup-wsl.sh`，将Python依赖与Qt基础库准备在项目内。该脚本需要可用的Python pip、apt包索引与网络。`bash scripts/run-wsl.sh` 仅供开发预览；其他电脑使用最终EXE不要求安装WSL。

命令行检查帧率：

```bash
python -m pcts_video_tool --inspect /path/to/video.mov
```

测试只生成独立合成视频，不读取工作区其他材料。测试覆盖计时、负TX、缺失值、短闪光、缺失变绿、真实解码回看、真实OCR、模型离线加载、GUI修正与任务切换、Excel公式缓存和证据导出。

打包配置同时生成PyInstaller目录模式和单文件模式。显式收集Qt平台/样式插件，保留Shapely动态库目录的正确大小写。标准一键脚本在Windows构建；也可以在Wine中运行Windows版Python与PyInstaller。源码包不包含虚拟环境、缓存或此前失败的构建产物。

安装包自检：`PCTSVideoTool.exe --self-test C:\path\self-test.json`。检查OCR、手部模型、视频解码和Qt渲染，并把结果写入指定文件。

## 文件结构

- `src/pcts_video_tool/`：数据计算、视频、检测、识别、流程、导出和Qt界面。
- `models/`：安装阶段准备的手部模型；OCR模型随RapidOCR发行包提供。
- `tests/`：独立测试及程序生成的素材。
- `build-windows.cmd`、`scripts/build_windows.py`、`packaging/`：一键Windows构建与冻结包自检。
- `requirements-windows.lock`、`requirements-linux.lock`：分别记录已验证平台的依赖版本。
- `docs/design.md`、`docs/implementation-plan.md`、`docs/validation.md`：设计、计划与验证记录。

开源组件：[PyAV](https://github.com/PyAV-Org/PyAV)、[OpenCV](https://github.com/opencv/opencv)、[RapidOCR](https://github.com/RapidAI/RapidOCR)、[MediaPipe](https://github.com/google-ai-edge/mediapipe)、[XlsxWriter](https://github.com/jmcnamara/XlsxWriter)、[PySide6](https://doc.qt.io/qtforpython-6/)。
